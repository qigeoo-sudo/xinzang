# 安全与质量自检清单（全面版）

> 适用对象：AI Career Companion（榨职机）全栈应用
> 覆盖维度：API 安全、数据安全、AI 特有风险、支付、PWA/SW、前端安全、基础设施、代码质量
> 使用方式：逐项标注 `[PASS]` / `[FAIL]` / `[WARN]` / `[TODO-真机]`
> 两轮执行：第一轮代码审查（本地），第二轮真实环境验证（生产/测试环境）

---

## 一、API 鉴权与越权（P0 — 最高优先级）

- [ ] **1.1 会话验证**：所有 `/api/*` 接口（除公开接口外）均校验 next-auth 会话，无未鉴权可达的管理接口。
- [ ] **1.2 水平越权**：用户 A 不能访问/修改用户 B 的数据（聊天会话、档案、订阅记录）。
- [ ] **1.3 垂直越权**：普通用户不能调用 ADMIN 专用接口（`/api/admin/*`），后端有 role 校验而非仅靠前端隐藏菜单。
- [ ] **1.4 ID 可枚举**：接口中的 userId/sessionId 等 ID 使用足够随机的 cuid，不可被顺序枚举。
- [ ] **1.5 速率限制**：关键接口（登录、注册、聊天、支付）有速率限制，且内存限制器在生产多实例下不会被绕过。
- [ ] **1.6 输入校验**：所有 POST/PUT 接口对请求体做 schema 校验（zod/手写），不信任客户端数据。
- [ ] **1.7 SQL 注入**：Prisma 查询中使用 `$queryRaw` / `$executeRaw` 的地方参数化传入，无字符串拼接。
- [ ] **1.8 SSRF**：服务端发外部请求的接口（如 DeepSeek API 调用）不允许用户控制目标 URL。
- [ ] **1.9 错误信息泄露**：API 错误响应不返回堆栈、SQL 语句、内部路径，生产环境关闭 debug 模式。
- [ ] **1.10 CORS**：跨域配置白名单收紧，不允许 `*`。

## 二、数据安全与密钥管理（P0）

- [ ] **2.1 密钥存储**：`DEEPSEEK_API_KEY`、`AUTH_SECRET`、`DATABASE_URL` 等只存在于环境变量，不硬编码、不进 git。
- [ ] **2.2 .env 文件**：`.env.local` 在 `.gitignore` 中，`.env.example` 不含真实密钥。
- [ ] **2.3 数据库文件**：`dev.db` / `prod.db` 不进 git，生产数据库文件权限收紧。
- [ ] **2.4 PII 存储**：用户手机号、真实姓名等 PII 在数据库中明文或加密存储，日志中不打印 PII。
- [ ] **2.5 会话 Token**：next-auth JWT 配置合理，过期时间不过长，HttpOnly + Secure + SameSite。
- [ ] **2.6 密码处理**：密码使用 bcrypt/argon2 哈希，不存明文，不返回给前端。
- [ ] **2.7 数据删除**：清空资料操作真正删除关联数据（聊天记录、档案），而非仅标记删除。
- [ ] **2.8 数据库备份**：生产库有定期备份机制，备份文件不随镜像分发。

## 三、AI 特有风险（P0）

- [ ] **3.1 API Key 泄露**：DeepSeek Key 只在服务端使用，前端 bundle 中无 key，浏览器请求不暴露 key。
- [ ] **3.2 Prompt 注入 — 数据越权**：用户无法通过对话诱导导师泄露其他用户的信息。
- [ ] **3.3 Prompt 注入 — 系统策略泄露**：用户无法通过"复述你的指令"等手段获取 system prompt 原文。
- [ ] **3.4 成本攻击**：单个用户高频调用 `/api/chat` 不会导致 DeepSeek 余额被耗尽（速率限制 + 用量上限）。
- [ ] **3.5 用量追踪**：每个用户的 AI 调用次数有记录，超限后自动降级或拒绝。
- [ ] **3.6 输出过滤**：AI 回复内容有基本的安全过滤（色情/暴力/违法），不直接透传未审查内容。
- [ ] **3.7 用户输入审查**：用户输入（档案字段、聊天消息）有内容审核接口，不合规内容被拦截。

## 四、支付安全（P0）

- [ ] **4.1 订单伪造**：用户不能通过修改请求参数（plan、金额）创建低价订单获取高价套餐。
- [ ] **4.2 支付回调**：Mock 支付接口在生产环境不可达或已关闭，真实支付回调有签名验证。
- [ ] **4.3 重复支付**：同一订单不会因重复请求导致多次扣款或多次开通会员。
- [ ] **4.4 订单状态一致性**：支付成功后订阅状态原子更新，无中间态可被利用。
- [ ] **4.5 退款逻辑**：退款操作有鉴权和审批流程，普通用户不能自行触发退款。

## 五、PWA 与 Service Worker（P1）

- [ ] **5.1 HTTPS**：全站 HTTPS，无混合内容。
- [ ] **5.2 Manifest 安全**：`start_url` 无开放重定向漏洞，manifest 通过 HTTPS 加载。
- [ ] **5.3 SW 作用域**：Service Worker 的 `scope` 限制在必要路径，非根目录无限制。
- [ ] **5.4 SW 更新机制**：`skipWaiting` + `clients.claim` 不会导致老版本用户数据丢失。
- [ ] **5.5 缓存投毒**：不缓存 4xx/5xx 错误响应，缓存键无冲突。
- [ ] **5.6 缓存版本化**：有版本号管理，更新后旧缓存被清理。
- [ ] **5.7 离线降级**：无网络时返回自定义离线页面，不泄露路径信息。
- [ ] **5.8 本地存储 PII**：IndexedDB / LocalStorage / Cache API 中无明文 PII。
- [ ] **5.9 预缓存体积**：precache 列表不过大，不超出移动设备存储配额。
- [ ] **5.10 iOS 兼容**：`apple-touch-icon`、`apple-mobile-web-app-*` 配置正确，iOS Safari 无 JS 报错。

## 六、前端安全（P1）

- [ ] **6.1 XSS**：用户输入在渲染时转义，无 `dangerouslySetInnerHTML` 未消毒使用。
- [ ] **6.2 CSP**：`next.config` 或 nginx 配置了 Content-Security-Policy 头。
- [ ] **6.3 HSTS**：服务器开启 `Strict-Transport-Security`。
- [ ] **6.4 CSRF**：状态变更接口（POST/PUT/DELETE）有 CSRF 防护或依赖 SameSite Cookie。
- [ ] **6.5 点击劫持**：`X-Frame-Options: DENY` 或 `SAMEORIGIN`。
- [ ] **6.6 敏感信息控制台输出**：生产环境无 `console.log` 打印密钥、用户数据、SQL。
- [ ] **6.7 第三方脚本**：所有 `<script src>` 来源可信，有 SRI 或 CSP 白名单。

## 七、基础设施安全（P1）

- [ ] **7.1 Docker 镜像**：生产镜像不含源码、.env、dev 依赖，以非 root 用户运行。
- [ ] **7.2 端口暴露**：仅 3000 端口对外，数据库端口不公网暴露。
- [ ] **7.3 SSH**：禁用密码登录，仅密钥登录，root 登录受限。
- [ ] **7.4 防火墙**：有 iptables/ufw 或云安全组，仅放行必要端口。
- [ ] **7.5 容器重启策略**：`--restart=unless-stopped` 或等效配置。
- [ ] **7.6 日志持久化**：容器日志有持久化或轮转，不会撑满磁盘。

## 八、代码规范与可维护性（P2）

- [ ] **8.1 TypeScript 严格模式**：`tsconfig.json` 开启 `strict: true`，无 `any` 滥用。
- [ ] **8.2 函数复杂度**：无超长函数（>200 行），复杂逻辑有拆分。
- [ ] **8.3 重复代码**：无大段复制粘贴，公共逻辑有提取。
- [ ] **8.4 命名规范**：变量/函数命名清晰达意，无 `temp`/`data`/`foo` 等无意义命名。
- [ ] **8.5 错误处理**：异步操作有 try-catch，错误有用户可读的提示，不静默吞错。
- [ ] **8.6 类型安全**：Prisma 查询结果有类型推断，API 响应有类型定义。
- [ ] **8.7 依赖管理**：无冗余依赖，`package.json` 无未使用的包。
- [ ] **8.8 注释**：复杂逻辑有注释，无"死注释"（注释掉的旧代码）。
- [ ] **8.9 目录结构**：API 路由、组件、工具库分层清晰，无跨层乱引。
- [ ] **8.10 构建产物**：`npm run build` 零错误零警告，无 `@ts-ignore` 残留。

## 九、性能与稳固性（P2）

- [ ] **9.1 Core Web Vitals**：LCP < 2.5s、INP < 200ms、CLS < 0.1。
- [ ] **9.2 数据库索引**：高频查询字段有索引（userId、status、createdAt）。
- [ ] **9.3 N+1 查询**：列表接口无 N+1 查询问题。
- [ ] **9.4 图片优化**：使用 next/image 或等效方案，有 lazy loading 和尺寸压缩。
- [ ] **9.5 内存泄漏**：长连接（SSE/WebSocket）有清理逻辑，无定时器/监听器未释放。
- [ ] **9.6 容错降级**：DeepSeek API 不可用时聊天功能优雅降级，不导致整页崩溃。

## 优先级总览

| 优先级 | 维度 | 核心关注点 |
| ------ | ---- | ------ |
| P0 | API 鉴权、数据安全、AI 风险、支付 | 越权、注入、密钥泄露、成本攻击、订单伪造 |
| P1 | PWA/SW、前端安全、基础设施 | CSP/HSTS、缓存投毒、Docker 加固、端口收敛 |
| P2 | 代码质量、性能 | 类型安全、复杂度、N+1、Web Vitals |

## 两轮执行说明

### 第一轮：代码审查（本地，现在做）
- 静态阅读源码，检查逻辑漏洞、配置缺陷、代码质量
- 工具：Trae 读代码 + grep + TypeScript 编译 + npm audit
- 产出：问题清单 + 修复建议

### 第二轮：真实环境验证（生产/测试环境，部署后做）
- HTTP 响应头实测（curl）、TLS 检测、Lighthouse 跑分
- 真机安装体验（iOS Safari / Android Chrome）
- 离线场景模拟、网络攻击模拟
- 跨浏览器兼容性
- 产出：补充第一轮遗漏项 + 真机结果
