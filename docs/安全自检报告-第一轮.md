## 四、关键设计说明：为什么多实例绕不过每日聊天上限

系统有两道独立闸门：

1. **突发频率闸门**（内存 Map）：每用户每分钟 60 次。多实例下按实例稀释——只防瞬时高频。
2. **配额闸门**（数据库 COUNT）：每次对话前查询 `ChatMessage` 表 24 小时滚动窗口 + 订阅周期内的**成功计费回复数**，超限直接 429，不调用 DeepSeek。

攻击者即使借多实例刷过闸门 1，闸门 2 查的是所有实例共享的同一个数据库，计数照常累加。**多榨包（mentorCredits）是超额的唯一合法途径。**

当前生产是单容器 + SQLite（单文件库本身不支持多实例写），闸门 1 完全有效，故本轮选择"维持现状 + 文档约束"（方案 A）。

## 七、迁移火山引擎 RDS MySQL 注意事项

> 背景：上公网前数据库由服务器本地 SQLite（`/app/data/prod.db`）迁至火山引擎 RDS MySQL。
> RDS 的向量/RAG 能力为可选项——当前知识检索是 Node 端知识卡匹配 + Prompt 组装，不依赖向量列；RAG 技术本身评估成熟前不引入，避免无关系绑。

### 7.1 Prisma 配置变更
- `prisma/schema.prisma`：`provider = "sqlite"` → `"mysql"`，`datasource url` 改读 `DATABASE_URL`（格式 `mysql://用户:密码@RDS地址:3306/库名`）。
- 生产建议改用正式迁移基线：`prisma migrate deploy`（或至少 `prisma db push` 后固化一版基线），替代长期 db push。

### 7.2 Schema 兼容性（必须逐项核查）
- **长文本字段是最大坑**：MySQL 连接器下 Prisma 的 `String` 默认是 **VARCHAR(191)**；SQLite 无长度限制。聊天内容、档案长文本、JSON 快照（`attributionJson`）等可能超 191 字的字段要显式加 `@db.Text` / `@db.MediumText`，否则建表能过、写入报错。
- `Json` 字段 SQLite 以文本存、MySQL 用原生 JSON 类型，Prisma 读写层透明，但 ETL 时注意内容必须是合法 JSON。
- 布尔值 SQLite 为 0/1、MySQL 为 TINYINT(1)，Prisma 自动处理。
- 唯一索引长度：长字符串唯一键在 MySQL 有索引字节上限；本项目唯一字段（手机号、邮箱、code、订单号）均短，无风险，迁移时复核一次。
- 大小写排序：MySQL 默认 collation 对英文大小写不敏感；邮箱注册已统一小写存储，无影响；如后续有区分大小写的精确匹配需求需注意。
- 枚举：SQLite 期状态字段均以 String 存储，迁移时保持 String 即可，不强制转 MySQL ENUM。

### 7.3 数据迁移
- Prisma 不支持跨 provider 直接搬数据。建议一次性 tsx ETL 脚本：用只读方式连旧 SQLite 读出，按外键依赖顺序（User → Profile/Subscription/Channel/ChatSession/ChatMessage…）写入 MySQL。
- 标准流程：RDS 建库 → `prisma db push`（或 migrate）建表 → ETL 全量搬运 → **逐表 count 对账 + 抽样字段比对** → 改容器 `DATABASE_URL` → 部署 → 冒烟（登录、对话计费、下单、后台统计）。
- 选低峰执行；迁移窗口内停写（停容器），旧 SQLite 文件保留至少 2 周做回滚兜底。
- 时间字段全部 UTC 存储，RDS 参数 `time_zone` 建议显式设 UTC，避免隐式时区转换。

### 7.4 连接与安全
- RDS 放入 VPC，应用服务器同 VPC 或安全组白名单访问；**3306 绝不对公网开放**；如必须跨公网则强制 TLS。
- Prisma 连接串按需带 `connection_limit` / `pool_timeout`，按 RDS 规格的 max_connections 核算（单容器默认池很小，够用；多实例时要重新算）。
- staging（CloudBase/main）与生产使用**不同的数据库实例和账号**，防止 staging 误连生产。
- 密钥只放 `/opt/xinzang/.env`（容器 env-file），不进镜像、不进 git。

### 7.5 运维切换
- 备份改为 RDS 自动快照 + binlog 时间点恢复（PITR），设置保留天数；**切换确认后删除本地 crontab 与 30-cron-backup.sh 的使用**（脚本保留也无害，但它只备本地 SQLite）。
- 数据卷 `/opt/xinzang-data` 在 MySQL 化后不再装主库，可在一次例行部署时清理。
- **限流升级前提**：多实例（水平扩容）前必须把 rate-limit 改为 Redis 或数据库实现（见 src/lib/rate-limit.ts 文件头注释）。
- RAG（向量列/向量索引）：如未来启用，单独做技术验证与容量评估，不与本次迁移捆绑。
